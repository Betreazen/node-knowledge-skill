# node-knowledge

Agent Skill для разработки на Node.js — на JavaScript и TypeScript, в любой области: веб-бэкенды и API, базы данных и очереди, боты, CLI, npm-библиотеки, скрипты и автоматизация, десктоп на Electron, бандлеры, скрапинг, AI/LLM- и MCP-приложения, IoT, код, который должен работать ещё и на Bun, Deno или Cloudflare Workers.

Скилл даёт ИИ-агенту (Claude Code, claude.ai и другим инструментам с поддержкой формата [Agent Skills](https://agentskills.io)) три вещи:

- **библиотеку знаний** — около 1500 ссылок на книги, статьи, доклады, документацию, пакеты и кодовые базы, разложенных по категориям. У каждой ссылки есть автор, год и пояснение, зачем её читать. Отдельно — таблица «симптом → техника → источник» для поиска решения по профилю или замечанию ревью;
- **тулчейн** — версии Node и график релизов, менеджеры пакетов, запуск TypeScript, ESLint, oxlint, Biome, Prettier, `node:test`, Vitest, защита цепочки поставок и `npm audit`: установка, команды, порядок шагов в CI, шаблоны `package.json`, `tsconfig.json`, `eslint.config.js`, `.npmrc` и workflow GitHub Actions;
- **пайплайн** — тесты до кода, проверки качества, бенчмарки, базовый замер и профиль, стандартное ревью, поиск решений в библиотеке, оптимизация и повторный замер. Правка оптимизации принимается, только если бенчмарк показал выигрыш на нескольких чередующихся прогонах.

Состояние знаний — ноябрь 2026: Node 26 (Active LTS), 24 и 22 (Maintenance LTS), TypeScript 7.0, npm 11 и 12, ESLint 10, Vitest 5. Сотни утверждений о поведении Node, npm, TypeScript и тестовых инструментов проверены запуском на Windows 11 с Node 24.17 (часть — на Node 26.13). Тексты справочников на русском, названия источников — в оригинале.

## Бенчмарки

Скрипт `bench_compare.mjs` работает без зависимостей на Node 18+ и читает JSON от mitata, JSON-репортёра Vitest 5, hyperfine и простой общий формат. Он сравнивает по 5 прогонов на сторону, снятых в отдельных процессах в порядке ABBA, и ставит вердикт `faster` или `slower`, только если медианы всех прогонов одной стороны лежат по одну сторону от другой. При регрессии код выхода 1.

При проверке скрипта нашлись две ловушки, которые учтены в пайплайне:

- **JIT нужно прогреть явно.** V8 оптимизирует функцию по числу вызовов, а не по времени. tinybench с коротким бюджетом времени показал результат в 16 раз хуже реального, потому что мерил код до оптимизации.
- **Трёх прогонов мало.** При сравнении кода с самим собой прогон, шедший сразу после более медленного варианта, оказался систематически на 6,5% быстрее, и три прогона дали ложное ускорение. Поэтому прогонов пять, а порядок чередуется.

## Установка

**Claude Code: для всех проектов**

```bash
git clone https://github.com/Betreazen/node-knowledge-skill.git
cp -r node-knowledge-skill/node-knowledge ~/.claude/skills/
```

**Claude Code: для одного проекта.** Скопируйте папку `node-knowledge` в `.claude/skills/` в корне проекта и закоммитьте её. Тогда скилл получит вся команда.

**claude.ai.** Заархивируйте папку `node-knowledge` в zip и загрузите в разделе Skills настроек claude.ai. Во frontmatter только стандартные поля `name` и `description`, поэтому загрузка проходит без ошибок.

**Другие агенты (Codex, Gemini CLI, GitHub Copilot, Cursor).** Скопируйте папку в `.agents/skills/` проекта. Этот путь читают большинство инструментов с поддержкой Agent Skills.

## Использование

Скилл срабатывает сам, когда задача касается Node.js: написание или ревью кода, выбор пакетов и инструментов, TypeScript, архитектура, асинхронный код, профилирование и оптимизация. В Claude Code его можно вызвать и явно командой `/node-knowledge`.

Примеры запросов:

- «Настрой в проекте ESLint, Prettier, проверку типов, `node:test` с покрытием и CI на GitHub Actions»
- «Профиль показывает много времени в `parseRow` — что можно сделать?»
- «Сделай ревью сервиса на Fastify по чеклистам серверного и асинхронного кода»
- «Проведи цикл оптимизации обработки запросов: бенчмарки, базовый замер, гипотезы из библиотеки, повторный замер»
- «Как опубликовать библиотеку в 2026 году: только ESM или dual, какой `exports`?»
- «Event loop блокируется под нагрузкой — как найти причину?»

## Пометки в справочниках

- `[устарело]` — у материала есть замена, и она указана рядом.
- `[не проверено]` — утверждение взято из одного вторичного источника; его стоит перепроверить.

Версии пакетов указаны на ноябрь 2026. Со временем они устаревают, поэтому перед важными решениями сверяйтесь с `npm view`, документацией и changelog. В 2025–2026 годах вышло много мажорных версий с ломающими изменениями (TypeScript 7 без JS API, npm 12 с блокировкой install-скриптов, ESLint 10, Vitest 5, многие пакеты стали ESM-only), и примеры из старых статей могут не работать.
